When the Safety Filter Fails:
Exact Diagnosis of Infeasibility in Multi-Robot
Control Barrier Functions

Chandan Kumar Sah1     Jishnu Keshavan1
1 Department of Mechanical Engineering, Indian Institute of Science, Bengaluru
Paper arXiv Code Interactive demo BibTeX

Sixteen underactuated robots. Every pair within sensing range is an enforced safety constraint, drawn as an edge coloured by the share θk,i of that constraint each endpoint is made responsible for. A single linear program chooses the division at every control step, and no local program is ever infeasible.

Why a flag is not enough

  The question

A multi-robot safety filter returns one bit when it fails. What should the designer actually change?

When several barrier constraints compete for the same bounded actuation, the quadratic program can become infeasible. The solver reports INFEASIBLE and stops there. It does not say which interaction caused the conflict, which robot would benefit from a stronger actuator, whether retuning the gains would help at all, or how the shared load should have been divided.

We derive an exact conic certificate whose sign decides feasibility and whose value answers all four questions from a single solve.

Four questions, four answers

The certificate splits the problem into a demand term, set by the barrier encoding, and a supply term, set by the geometry of the input sets. Each question lands on one side of that split.

Will tuning the gains help?

No — the supply is invariant

The input coefficients of the barrier chain are independent of every class-K function, so no amount of retuning creates capability. Exactly one exception exists, through an off-chain penultimate gain, and it acts only in advance of a conflict.

Which robots are worth upgrading?

The ones with nonzero leverage

The certificate's multiplier gives each robot's marginal value of actuation, ∂M/∂ρi. It is exactly zero for most robots: their thrust axis is annihilated by the constraint they carry, and a tenfold upgrade changes nothing.

Which interaction causes the conflict?

The support of the multiplier

The optimal multiplier is sparse, naming a handful of pairs regardless of fleet size. Relaxing the pair it names restores feasibility in 94% of observed conflicts, against 4–6% for the usual heuristics.

How should the load be shared?

By a single linear program

Because the certificate prices any division of a shared constraint exactly, the optimal division solves one linear program — computed centrally on the joint state, then broadcast so each robot filters its own input locally, in parallel.

The same task, three ways

Identical initial conditions, goals and actuation bounds; only the division of each shared constraint differs. The uniform and capability-weighted splits leave some local program infeasible on 45% and 32% of steps and both fleets stall; the certificate-optimal split does so on 0.3% and holds the worst local margin positive throughout.

What it does not do

The allocation targets feasibility, not liveness, and the two are in tension. A heuristic split that leaves a local program infeasible lets the robot relax its own share through a slack variable and move without honouring the constraint: it makes progress, and violates the safety distance in five times as many runs. Enforcing a constraint is necessarily more restrictive than enforcing it only when convenient, and the proposed allocation reaches fewer goals (28.9% against 43.4%) as a result. Deadlock is a known limitation of CBF quadratic-program filters generally; resolving it needs machinery beyond the certificate, which we regard as complementary rather than competing work.

Abstract

Pointwise infeasibility of multi-robot control barrier function safety filters offers little guidance on its underlying cause. We derive an exact conic certificate whose sign decides feasibility and whose value separates the problem into a demand term, controlled by the barrier encoding, and a supply term, controlled by the geometry of the input sets. The supply is invariant to the choice of class-K functions, so retuning gains cannot create capability; there exist structurally degenerate states at which no increase in actuation restores feasibility; and the certificate's multiplier is sparse, naming the few interactions and agents responsible for a conflict. Because the certificate prices any division of a shared constraint exactly, the optimal division is the solution of a single linear program, solved centrally and executed locally. Across 320 paired closed-loop runs it reduces infeasible control steps from about 50% for the uniform and capability-weighted heuristics to 6.0%, matching a centralized filter, and cuts runs containing a safety violation from 118/160 to 23/160, at 2.3 ms per step.
